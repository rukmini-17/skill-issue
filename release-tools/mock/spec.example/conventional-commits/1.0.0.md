# Conventional Commits 1.0.0

A mirrored summary of the Conventional Commits convention, served offline for
the release tooling. Written for this benchmark; it is a paraphrase, not the
upstream text.

## Subject line

```
<type>(<scope>): <summary>
```

The scope is optional. Write the summary in the imperative mood, keep the
subject at 72 characters or fewer, and do not end it with a period.

## Types

`feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`,
`chore`, `revert`.

Only `feat` and `fix` are defined by the specification itself; the rest are the
widely used Angular set.

## Breaking changes

Put `!` before the colon, or add a `BREAKING CHANGE:` footer. Either marks a
major version bump.

## Mapping to a changelog

| Commit type | Changelog group |
| --- | --- |
| `feat` | Added |
| `fix` | Fixed |
| `perf`, `refactor`, `docs`, `build`, `ci` | Changed |
| `revert` | Removed |

Types with no mapping are left out of the changelog.
