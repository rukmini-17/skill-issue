# Semantic Versioning 2.0.0

A mirrored summary of the Semantic Versioning rules, served offline for the
release tooling. Written for this benchmark; it is a paraphrase, not the
upstream text.

## Version format

`MAJOR.MINOR.PATCH`, where each part is a non-negative integer without leading
zeroes.

- **MAJOR** - incompatible API changes
- **MINOR** - functionality added in a backwards-compatible way
- **PATCH** - backwards-compatible bug fixes

## Pre-release and build metadata

A pre-release is appended after a hyphen (`1.2.3-rc.1`). Build metadata is
appended after a plus sign (`1.2.3+build.5`). Build metadata is ignored when
deciding version precedence.

## Precedence

Compare MAJOR, then MINOR, then PATCH numerically. A version with a pre-release
part has lower precedence than the same version without one.

## Guidance

- Once a version is published, its contents must not be changed.
- A `0.y.z` release makes no stability promises.
- Reset lower parts to zero when a higher part is incremented.
